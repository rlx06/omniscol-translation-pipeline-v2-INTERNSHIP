# Cross-Language Audit Findings — Omniscol Translation Pipeline V2

Generated by running the V2 semantic validator (`audit-v2` logic, no LLM
calls) against all 14 real production language files in `languages/`,
covering both `login` and `webapp` modules (28 files, ~1,289 keys each
module). This required first fixing 3 broken files (see below) that
would otherwise have been silently unreadable.

## 0. Data integrity bugs found in the raw files (before any translation
   analysis was even possible)

| File | Problem | Fix |
|---|---|---|
| `russian,L-f.json` | Invalid JSON — a stray character before the opening `{` | Strip the stray character; verified it then parses correctly (66 valid keys) |
| `portugese.W-f.json` | Wrong structure — all 1223 keys sit at the top level instead of nested under `"translations"` | Re-wrap under `"translations"` |
| `vietnamese.W-f.json` | Same wrong structure as Portuguese | Re-wrap under `"translations"` |

Any code (including V1's own scripts) that expects `data["translations"]`
would get nothing usable from the Portuguese/Vietnamese webapp files, and
would crash outright on the Russian login file, as-is.

## 1. Systemic concept-confusion bugs (found via the semantic validator)

These are the "Class ≠ Lesson, Group ≠ Class" style errors the technical
lead's document explicitly called out. Same underlying bug, repeated
across many languages independently — strong evidence this is a systemic
translation-process gap, not a one-off typo.

| Bug | Languages affected | Not affected |
|---|---|---|
| `action.activate` / `action.enable` translated identically | ar, de, es, it, kz, ml, pl, pt, ru, vi, zh (11) | en, nl, he |
| `diagnose.problem.timesetdupl.descr` / `spacesetdupl.descr` identical | ar, de, en, es, he, it, kz, ml, nl, pl, pt, ru, vi, zh (all 14) | — |
| `subjects.import.from_class` / `groups.import.from_class` identical | ar, en, es, he, it, kz, pl, pt, ru, vi, zh (11) | de, ml, nl |
| `&nbsp;` silently dropped in `sched.hours_distribution` / `sched.spaceset` | ar, de(partial), en, es, he, kz, pl(n/a - has it), pt, ru, vi, zh (11) | it, ml, nl |

The `timesetdupl`/`spacesetdupl` one is the most interesting: it fails in
literally every single language, which suggests the issue may trace back
to how these two diagnostic message templates were originally written or
copied, not to translation quality per se — worth checking the French
source (`data/source/fr_webapp.json`) for these two keys directly.

## 2. A concrete, demonstrable regression (not a translation-quality issue)

In `it_webapp_corrected.json`, four keys have the CSS/FontAwesome icon
class `fa-user-plus` translated into **`fa-utente-plus`**
("utente" = "user" in Italian):
- `admin.students.add.info`
- `class.teachers.assign.info`
- `admin.teachers.add.info`
- `class.teachers.assign.lesson.info`

CSS class names must never be translated — this breaks the icon in the
Italian UI. This is the strongest single item to show your lead: it's not
a matter of translation *quality*, it's a rendering bug already live in
production Italian.

## 3. Placeholder bugs specific to a few languages

- `zh_webapp`: `sched.timeset.info` and `sched.spaceset.info` have a
  `{class}` placeholder that doesn't exist in the French source at all —
  likely copy-pasted from a neighboring key.
- `zh_webapp`: two `diagnose.problem.course_distance_*.descr` keys have an
  extra `{gap}` placeholder not present in French.
- `de_webapp`, `kz_webapp`, `vi_webapp`: `format.name.short` has an extra
  `{middle_name_short}` placeholder not present in French — same pattern
  in 3 languages, suggesting the French source was simplified after these
  were translated and the old placeholder was never removed downstream.

## 4. Sync backlog (not a bug — a known gap)

`de_webapp`, `en_webapp`, `kz_webapp`, and `nl_webapp` are all missing the
exact same set of ~9-11 keys (`action.visualize`, `action.reorganize`,
`error.upload.size_exceeded`, `admin.parameters.namecapitalize`, etc).
Because even the English pivot file is missing them, this looks like
keys that were added to the French source after these four files were
last generated/synced — a straightforward candidate for V1's existing
`sync-missing-keys` command, not a translation defect.

## 5. A limitation in the V2 validator itself (flagged honestly, not hidden)

`school_not_found.info` shows up as an "HTML tag mismatch" in nearly every
language. This is a **false positive**: the validator compares the entire
`<a href="mailto:...">` tag as one string, and the `href` legitimately
contains a translated email-subject line per language. The fix is to
compare tag names/structure only, not full attribute strings — tracked as
a follow-up in `PLAN.md`.

## Bottom line

Running the new semantic + structural validators against real production
data (zero LLM calls, entirely deterministic) found:
- 3 file-level data corruption bugs
- 4 classes of systemic concept-confusion bugs spanning most of your 14
  languages
- 1 concrete UI-breaking regression (Italian icon class)
- 2 real placeholder-integrity bugs
- 1 sync backlog (expected, not a defect)
- 1 known false-positive in the validator itself, disclosed rather than
  hidden

This is the strongest evidence to bring to your supervisor that the new
architecture adds value beyond V1: these are bugs V1's own pipeline and
audit process did not catch.
